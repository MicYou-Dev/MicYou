# 用户指南

面向 MicYou 用户的插件使用说明：安装、卸载、GUI 管理、配置与跨端同步

## 安装插件

### 从插件市场安装（推荐）

设置-插件 → 点「插件市场」按钮 → 浏览列表 → 点「安装」→ 核对能力清单后确认

- 市场读取 MicYou-Plugins 仓库的 index.json（GitHub Pages 部署，根除 CDN 缓存）
- 安装前先拉取远程 manifest 展示能力供确认，确认后才下载 zip 安装
- 已安装的插件在市场列表显示「已安装」


### 手动安装（离线 / 开发者模式）

插件分发包含**插件目录**（含 `plugin.json` 与入口文件）与 **ZIP 压缩包**：

1. 打开应用，进入 **设置 → 插件** 页面
2. 点击「打开插件目录」定位宿主插件存放路径：
   - Linux / macOS：`~/.config/micyou/plugins/`
   - Windows：`%APPDATA%\micyou\plugins\`
3. 将解压后的插件文件夹放入该目录（每个插件单独一个子目录）
4. 返回插件设置页面点击「刷新」

> 手动导入 ZIP 包时，系统会自动解析并展示权限清单（请求的能力、作者、许可等），经用户确认后方可载入。

## 卸载插件

- 在插件列表中点击垃圾桶图标确认卸载，插件将被禁用并从磁盘删除。
- 也可以直接在操作系统的插件目录中手动删除对应的插件文件夹，刷新后生效。

## 在 GUI 中管理插件

| 操作 | 说明 |
| --- | --- |
| 启用 / 禁用 | 卡片右侧开关（启用时即刻载入运行时并接入 DSP 链路） |
| 卸载 | 移除插件并清理本地文件 |
| 查看日志 | 查看该插件独立的环形日志输出（最多保留 500 行） |
| 编辑配置 | 弹出配置编辑器，保存后写入本地持久化存储 |
| 跨端状态 | 查看与移动端的插件消息同步连通状态 |

## 插件专属设置页

声明了 `ui.panels` 的插件，会在设置对话框的侧边栏动态添加专属设置面板。页面由插件自带的自包含 HTML 在沙箱中渲染，支持与宿主双向通信。

## 全局快捷键

支持注册系统全局快捷键的插件（如 Soundpad），在应用处于后台或全屏游戏状态下依然能响应热键动作。

## 音效板（Soundpad 类插件）

- 启用音效板类插件后，主界面将展示音效网格按钮。
- 点击按钮即可触发音频混音播放，音效将直接混入虚拟麦克风通道，通话对端与本地均可收听。
- 用户可直接在插件配置中增减音频文件映射。

## 更新插件

若插件在 Manifest 中声明了 `updateUrl`，可在插件卡片中点击「检查更新」。发现新版本后可一键下载更新并平滑重载。

MicYou 桌面端每次启动还会在后台自动检查一次插件更新（不阻塞启动、失败静默）。检查结果会被缓存：打开「设置 → 插件」即可看到更新横幅，无需再手动点一次；工具栏的「检查更新」仍可随时强制刷新。

## 配置插件参数

1. 打开插件面板，点击对应卡片的配置图标
2. 在编辑器中按需修改 JSON 配置，例如：

```json
{ "gain": 2.0, "threshold": -40.0 }
```

3. 点击「保存」即可生效（部分实时 DSP 插件可能需要重新启用一次以使底层算法重新初始化）

## 跨端插件同步

当手机（安卓客户端）与电脑建立连接后，两端的插件系统自动可通信：

- 手机插件与电脑插件通过同一消息协议（`PluginMessage`）互发消息
- 电脑插件可用 `message.send` 定向到 `remote` 目标（如手机上的传感器插件）
- 手机插件采集的数据（传感器、电池等）可实时推给电脑插件处理，处理后结果回传
- 跨端状态在插件面板右上角显示（设备已连接）

> 说明：安卓端插件运行时按规划将在后续版本提供，协议与总线已就绪，当前安卓客户端仅提供基础控制消息，插件消息通道对安卓端属于预留能力

## 常见问题

### 插件显示加载失败

检查：入口文件名与 manifest `entry` 是否一致、平台是否在 `platforms` 中、`apiVersion` 是否为宿主支持的 1 或 2、`minHostVersion` 是否高于当前 MicYou 版本、Native 插件是否为本平台构建产物

### 启用插件后声音异常 / 静音

立即禁用该插件；实时 DSP 插件质量问题（爆音、缓冲）通常源于插件未遵循实时安全规范，详见[开发指南](development-guide.md#实时-dsp-插件规范)

### 插件配置不生效

确认插件已启用并重新加载（禁用 → 启用），或查看插件日志确认 `get_config` 是否读取到值
